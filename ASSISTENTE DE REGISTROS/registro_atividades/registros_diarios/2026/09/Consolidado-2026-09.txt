Concerto do Documentaizer

A reelaboração do Documentaizer irá incluir a utilização da biblioteca Pyside6, por oferecer um resultado melhor.
O programa deve ser escalável, ou seja, deve ser feito por partes, a primeira que deve ser feita é a janela principal, ela deve ser dividida em 3 colunas, cada coluna representara cada uma delas representara uma das etapas do processo e por consequência e organização, cada uma terá um script único, uma das metas para manter a organização é reduzir a quantidade de scripts.
O primeiro script a ser desenvolvido é o Main. ele terá como objetivo deixar reservado os espaços de cada etapa. além disso ele deve ter a funcionalidade de encontrar a pasta onde estão os arquivos que serão manipulados. a janela do programa será divido nas seguintes áreas, considerando todo a área da janela no topo de borda a borada uma pequena área para Inserir o nome do município e um buscador de pasta, para o usuário buscar a pasta onde estão salvos os documentos contratuais do município. em baixo dessa área, estarão 3 retângulos lado a lado, cada um deles será onde ficará as partes de cada uma das etapas do programa que serão elaboradas em seguida. fazendo uma analise de objetos, eu quero que seja elaborado agor a o cpodigo do Main. ele terá como objetos o nome do município e o endereço da pasta de arquivos do município. deve utilizar o pyside6

Documentaizer/
│
├── Main.py
├── Etapa1.py       # será desenvolvido depois
├── Etapa2.py       # será desenvolvido depois
└── Etapa3.py       # será desenvolvido depois

Primeiras modificações:
1. A janela deve ter a opção de ocupar a tela inteira (deixando é claro apenas a barra de tarefas), como se fosse uma janela de navegador de internet por exemplo.
2. a área onde estão as informações de nome do município e o endereço da pasta dos arquivos dele deve se chamar internamente no programa de "area_inicial" e é assim que vamos nos referir a ela daqui pra frente.
3. a area_inicial deve ter uma altura de 10% da janela inteira, da maneira que elea está atualmente ela ocupa muito espaço.

Primeira etapa - Renoemação
A primeira etapa é a renomeação dos documentos da pasta para um modelo padrão, o objetivo é facilitar o trabalho do usuário.
a nomeação dos documentos segue um padrão, de forma que ele será montado por botões, porém pode ser que esse padrão seja atualizado no futuro então é importante no códigi um local apenas para definilo.
Na área da primeira etapa que vamos passar a nos referir a ela como area_etapa_1, a primeira coisa que deve aparecer nela é uma lista mostrando todos os documentos presentes na pasta que o usuário selecionou na area_inicial. Essa lista deve ocupar metade do espaço da area_etapa_1, e caso não consiga comportar todos os arquivos da pasta deve possuir então uma barra de rolagem para que o usuário possa ver todos os arquivos. essa lista deve permitir que o usuário selecione um item para ser manipulado.
Abaixo da lista irá ficar os botões para montagem do novo nnome do documento. no caso esse botões devem ser listas retrateis. elas devem ficar uma em cima da outra, e acima delas deve estar uma label mostrando uma preview do novo nome do documento. cada lista retrátil deve ser preenchida com uma lista fixa que será salva dentro do próprio código da etapa 1. haverá momentos em que o preenchimento de uma caixa de seleção será alterado de acordo com o item que foi selecionado previamente em outra caixa de seleção. Vamos para como essas listas retrateis devem estar organizadas
A primeira será o tipo de documento, ela deve apresentar as seguintes opções: Contrato, Procuração, Aditivo, Relatório de Assinaturas, Kit Prefeito, Publicação.
A segunda caixa é variável, caso a opção selecionada na primeira tenha sido Contrato, Procuração, ou Kit Prefeito ela deve ficar inativa. Se A primeira opção tiver sido Aditivo a caixa de seleção deve apresentaer as seguintes opções 1, 2, 3, 4, 5. Se a primeira opção tiver sido Relatório de Assinaturas a lista deve apresentar: Contratoo, Procuração, Aditivo. Se a primeira opção tiver sido Publicação, a lista deve apresentar Contrato ou Aditivo.
A Terceira caixa de seleção deve aparecer apenas se a segunda caixa tiver sido selecionado Aditivo. se esse for o caso a lista apresentada deve ser 1,2,3,4,5.

Montagem do nome do arquivo.
O nomde do arquivo deve ser composto pelo nome do município informado pelo usuário e pelo conteúdo das caixas de seleção em ordem. o texto deve ser em caps, retirados acentos e caracteres como "Ç" que podem gerar qualquer problema na nomeação de arquivos. sempre que algum item for selecionado nas listas retrateis o nome na label de preview deve ser atualizado. No fundo da area_etapa_1 deve haver um botão que aplique a renomeação, esse botão também deve fazer a verificação se esse nome estpa disponível para renomeação, prevenindo qualquer problema que possa vir a acontecer.
